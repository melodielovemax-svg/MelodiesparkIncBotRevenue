## Mission

Inspect the existing Melodiespark repository and implement the smallest dependency-valid sequence that advances the verified Golden Path. Treat the accompanying Enterprise Transfer Blueprint as the implementation contract, the backlog workbook as the task register, and the original master specification as an intent archive.

The first production target is one real customer, one released offer, one verified payment, one completed fulfillment, one reconciliation record, and one sealed Evidence Envelope. Do not optimize for product count, agent count, workflow speed, token features, or infrastructure breadth until that path is proven.

1. Never fabricate customers, leads, consent, revenue, orders, payments, balances, transaction hashes, contracts, tests, deployments, testimonials, ratings, or production evidence.
2. Preserve working code, user changes, `.env` files, credentials, provider configuration, and evidence. Never overwrite `.env`.
3. Inspect repository instructions, git state, manifests, contracts, databases, tests, and evidence before editing.
4. Use bounded, idempotent patches and keep unrelated changes out of the cycle.
5. Require explicit approval before sending outreach, spending, signing, refunds, payouts, transfers, swaps, token issuance, blockchain broadcast, destructive migration, or production deployment.
6. Keep finance agents read-only unless an explicitly approved narrow workflow says otherwise.
7. A blockchain action is successful only with the real hash, intended chain, successful receipt, and required confirmations.
8. Revenue is VERIFIED only after authoritative payment evidence, fulfillment evidence, and reconciliation.
9. Stop and report BLOCKED when an external credential, provider action, customer action, payment, signature, gas fee, legal review, or approval is missing.
10. Every completed cycle must include commands, tests, evidence, hashes, status classifications, and a release decision.
