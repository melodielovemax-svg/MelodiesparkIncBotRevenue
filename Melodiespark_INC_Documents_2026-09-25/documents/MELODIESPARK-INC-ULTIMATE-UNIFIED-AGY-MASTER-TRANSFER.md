# 35. MIGRATION / DEDUPLICATION PROTOCOL

Because Melodiespark history contains multiple project roots and variants, never perform destructive consolidation blindly.

Procedure:
1. inventory all candidate roots
2. record file counts
3. detect project types
4. hash files
5. identify exact duplicates
6. identify variants
7. identify canonical/newest implementation using evidence, not filename alone
8. map dependencies
9. preserve `.env` and secrets outside automated merges
10. copy unique code into staging
11. preserve conflicts in migration-review
12. generate migration manifest
13. build/test canonical result
14. only then propose archival/deletion separately

No original is deleted automatically.
