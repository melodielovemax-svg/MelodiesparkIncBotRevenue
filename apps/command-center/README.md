# Melodiespark Command Center

**Version:** 0.1.0  
**Runtime:** Node.js 22.5+ (tested on Node 24)  
**Mode:** Local, security-first control plane

Melodiespark Command Center is a working reference implementation for commerce reconciliation, bounded workflow automation, read-only integration adapters, non-custodial wallet verification, and governance evidence.

It is intentionally **not**:

- a bank, exchange, custodian, or regulated financial institution;
- a license, registration, or legal authorization;
- a guaranteed-revenue, infinite-profit, or autonomous-money system;
- a place to paste API keys, bank details, passwords, or private keys;
- a bridge that bypasses KYC/AML, tax, sanctions, wallet confirmation, or human approval.

## What is operational now

- Responsive dark/light dashboard with eleven sections.
- Demo mode with clearly labeled sample ledger records.
- SQLite persistence and a normalized production-oriented PostgreSQL schema.
- Scrypt password hashing, server-side sessions, CSRF protection, rate limits, audit logs, and security headers.
- Shopify order read adapter and signed webhook ingestion.
- Stripe balance/payout read adapter and signed webhook ingestion.
- Public USD reference-price feed with caching and a non-quotation disclaimer.
- MetaMask/EIP-191 connection and signature verification through `viem`.
- Optional read-only Ethereum native-balance lookup.
- Canonical, expiring withdrawal **authorization intents**. Signing one does not submit a transaction or move funds.
- 600 deterministic guardian/sub-guardian configuration profiles.
- Safe workflow cycles that validate health, ledger integrity, integration readiness, security configuration, and product catalog integrity.
- Product drafts, not automatic publishing.
- Internal Karma ledger boundary with no token conversion.
- One PowerShell launcher for initialization, password setup, safe cycles, and startup.

## Quick start

```powershell
Set-ExecutionPolicy -Scope Process Bypass
cd C:\melodie\MelodiesparkCommandCenter
.\Start-Melodiespark.ps1 -Initialize -SetPassword -Open
```

Open `http://127.0.0.1:4173` if the browser does not open automatically.

The first command:

1. installs the single runtime dependency (`viem`);
2. creates a local `.env` with random session secrets;
3. creates the SQLite database and 600 guardian profiles;
4. prompts for a 12+ character administrator password;
5. starts the local server.

No supplied password is embedded in the project.

## Useful commands

```powershell
# Run the automated test suite
npm test

# Run one local validation cycle
node scripts/run-safe-cycle.mjs 1

# Run three finite cycles
.\Start-Melodiespark.ps1 -Cycles 3

# Run one bounded Quantum Matrix adapter cycle
npm run quantum-matrix -- 1 --interval=30

# Optional continuous safe scheduler (minimum 30 seconds; no financial actions)
.\Start-Melodiespark.ps1 -Continuous -IntervalSeconds 300

# Regenerate the deterministic guardian registry
node scripts/generate-guardians.mjs

# Public, unauthenticated inventory of the configured application URLs
node scripts/scan-public-sites.mjs

# Create a source ZIP without .env, node_modules, or the local database
.\Package-Melodiespark.ps1
```

The continuous runner is deliberately bounded to read-only/local validation. It does not place trades, publish products, sign blockchain transactions, or call payout providers.

The Quantum Matrix adapter is a naming and phase-mapping layer over the same
safe runner. Its `alpha`, `beta`, `theta`, `delta`, `bravo`, and `gamma`
labels do not create additional agents, blockchain operations, Polygon
transactions, financial actions, or infinite scaling. It accepts only finite
cycles from 1 to 10,000 and an interval from 30 to 86,400 seconds.

## Configuration

Copying `.env.example` manually is supported, but the PowerShell initializer is preferred. Important variables:

| Variable | Purpose | Default |
|---|---|---|
| `APP_MODE` | `demo` or a future reviewed live mode | `demo` |
| `REQUIRE_AUTH` | Require authentication for reads | false in development, true in production |
| `ADMIN_EMAIL` | Local administrator identity | `admin@example.invalid` |
| `ADMIN_PASSWORD_HASH` | Scrypt password hash | unset until setup |
| `SESSION_SECRET` / `PORTAL_SECRET` | Random server secrets | generated by initializer |
| `SHOPIFY_STORE_DOMAIN` | `*.myshopify.com` custom-app domain | unset |
| `SHOPIFY_ADMIN_ACCESS_TOKEN` | Server-side Shopify token | unset |
| `STRIPE_SECRET_KEY` | Restricted server-side Stripe key | unset |
| `ETHEREUM_RPC_URL` | HTTPS or localhost RPC for read-only balance | unset |
| `ALLOW_REMOTE_WEBHOOKS` | Enables signed webhook routes | false |
| `ENABLE_SAFE_SCHEDULER` | Local safe scheduler | false |

Never put secrets in `public/`, browser storage, screenshots, chat transcripts, or a committed `.env`. Use a secret manager and restricted keys in deployed environments.

## API overview

See [`docs/API.md`](docs/API.md). Mutating endpoints require:

- a valid administrator session;
- `X-CSRF-Token` returned by login/status;
- same-origin browser context;
- request validation and rate limiting.

The wallet withdrawal flow is:

```text
Connect wallet
  → GET /api/wallet/challenge
  → personal_sign(challenge)
  → POST /api/wallet/verify
  → POST /api/withdrawal-intents
  → personal_sign(canonical intent)
  → POST /api/withdrawal-intents/:id/sign
  → signature_verified_pending_review
```

The final state is a review record. There is intentionally no endpoint that silently sends ETH, swaps tokens, or withdraws fiat.

## Validation status

`npm test` covers:

- password hashing and verification;
- canonical withdrawal intent binding;
- amount validation;
- health/configuration/demo ledger;
- authentication and session cookie;
- CSRF rejection;
- safe workflow execution;
- product draft creation.

A green test suite means the local implementation is internally consistent. It is **not** a legal opinion, security certification, exchange integration certification, or production readiness sign-off.

## Deployment

For a local container:

```powershell
docker compose up --build
```

For cloud deployment, read [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md). Production requires HTTPS, a managed secret store, a managed database, backups, monitoring, KYC/AML review, and a human owner for every financial action.
