# TESTS

Test suites that **pass in this environment**. **Empty until an operator
populates it.**

## The rule

A test that has not been run is not evidence. A suite belongs in this directory
only if someone executed it, in this environment, and watched it pass. Paste the
command and the result next to it:

```bash
# the command that was actually run
npm test
python -m unittest discover -s tests

# and the observed result
# tests 22
# pass 22
# fail 0
```

A suite that fails is still worth keeping — it documents a real gap. Just do not
describe it as passing.

## What belongs here

- Executable test code
- Fixtures the tests need
- The commands and results that prove the tests run

## What does not belong here

- **Test code copied from the source tree on faith.** 228 test files are
  catalogued in the `TEST` category. Catalogued means they exist, not that they
  pass, and certainly not that they pass against *your* code.
- **Expected-output files generated by the test run itself.** Regenerate them.

## Populating it

```bash
melodie inspect --category TEST --limit 100
melodie extract "tests/test_policy.py" --out ./TESTS
```

Then run them here and record the result. A test directory with no recorded
result is an archive, not evidence.
