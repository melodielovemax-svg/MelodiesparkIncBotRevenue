# Status Policy

## OPERATIONAL

Requires:

1. implementation exists
2. automated tests pass
3. runtime behavior is verified
4. required external dependencies are verified
5. evidence is retained

For business capabilities, real-world evidence is additionally required.

## SCAFFOLD

Implementation exists, but operational evidence is incomplete.

## PLANNED

The capability is intended but not sufficiently implemented for verification.

## PAPER-ONLY

The capability exists only as architecture, documentation, specification, or design.

## BLOCKED

Implementation exists but cannot currently operate because of a documented blocker.

## UNVERIFIED

Available evidence is insufficient to establish a stronger status.

## FICTIONAL

Narrative-only content.

## Prohibited Promotion Criteria

A capability cannot become OPERATIONAL because of:

- documentation
- architecture elegance
- UI polish
- containerization
- code volume
- security hardening
- marketing language
- naming
- fictional narrative
